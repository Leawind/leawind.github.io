# 交互、准星与渲染

## 重新定义“玩家看向哪里”

越肩相机与玩家眼睛不在同一点，若仍使用原版射线，屏幕中心附近的目标会与实际交互目标错位。SSR 为此建立 `PickContext`：它同时描述实体、相机、射线起点（玩家或相机）、射线方向（玩家朝向或相机朝向）和液体规则。

`ObjectPicker` 先进行方块检测，再把方块命中距离作为实体检测上限；实体检测沿上下文射线扩展 AABB 并调用原版 `ProjectileUtil.getEntityHitResult`。这样实体不会穿过前方方块被选中。

为让所有常见交互都使用这一语义，Mixin 分别替换：

| 原版位置                             | 替换结果                                            |
| ------------------------------------ | --------------------------------------------------- |
| `Player.pick`                        | 方块射线从 `PickContext` 生成，而不是固定用玩家视线 |
| `LocalPlayer.pick`                   | 实体命中检测改用 `ObjectPicker.pickEntities`        |
| `Item.getPlayerPOVHitResult`         | 桶等“玩家 POV 命中”物品使用相机语义的 `ClipContext` |
| `ProjectileUtil.getHitEntitiesAlong` | 新版攻击范围检测也从相机语义构建起止点              |

因此改动不只影响屏幕准星，也实际影响客户端发起的攻击、使用和方块交互的目标选择。

## 准星如何移动到真正目标

`CrosshairRenderer` 每个渲染帧从相机做主射线，取得实际命中点后将“命中点减相机坐标”依次乘模型视图矩阵与投影矩阵，最后换算为 HUD 中心的像素位移。这就是动态准星的位置。

准星模式包括静态、自适应、动态及带“瞄准时第一人称回退”的变体：

- **静态**：通常在屏幕中央，但仍可计算遮挡射线；方块和实体射线起点可分别配置。
- **自适应**：仅在被事件/API 识别为“瞄准”时采用动态行为；物品 ID、动画和数据组件可作为触发条件。
- **动态**：始终把 HUD 准星投影到相机射线实际命中点；可选择射线方向来自相机或玩家。

静态准星还会从主命中点构造第二条“遮挡”射线。若它在屏幕上的偏移足够大，模组显示遮挡指示符；瞄准时可用带叉准星代替。`HudMixin` 与 `GameRendererMixin` 修改原版“仅第一人称显示准星”的判定，并在绘制前后平移 GUI PoseStack，复用原版准星渲染。

## 玩家模型透明与渲染顺序

越肩相机靠近角色头肩时，模型会挡住视野。`CameraEntityRenderer` 在提交相机实体的渲染状态时进入“正在渲染相机实体”上下文，计算最大透明度后，`SubmitNodeCollectionMixin` 将其压入模型颜色的 alpha 通道。相机落在实体包围盒内、仰视达到阈值或望远镜瞄准时，会直接跳过自身模型。

默认透明度取决于相机横向/纵向偏移与实体包围盒的比例，最小 alpha 为 `0.15`；可选在瞄准时用 5 tick 渐变淡出。攀爬可选择保持不透明，以免透明模型妨碍攀爬判断。盔甲与附魔光效还通过 `RenderTypesMixin` 换成半透明渲染类型，避免“身体透明而盔甲不透明”。这依赖原版 Improved Transparency/Fabulous 渲染能力，部分第三方模型无法自动兼容。

## 其他渲染与音频一致性

- 将越肩当作第一人称传给 `AbstractClientPlayer.getFieldOfViewModifier`，保持疾跑、瞄准等 FOV 修正；`CameraMixin` 还可覆盖为固定 FOV。
- `GameRenderer` 可强制开/关视角晃动，并改变 3D 调试准星的可见性判定；调试屏加入模组状态文字。
- 解耦时指南针角度取独立相机 yaw，而不是角色可视 yaw。
- 可选“玩家声音居中”：实体绑定声音在客户端播放时改用根据相机计算的位置，减弱声音随留在画面边缘的角色而偏移的感觉。
